# Що приготувати?

Сайт, який підказує, що можна приготувати з продуктів, що вже є у вас у холодильнику.

## Про проєкт

Часто в холодильнику є кілька продуктів, а що з них приготувати — незрозуміло. Цей сайт вирішує проблему.

Користувач веде список продуктів у своєму холодильнику: що саме є, скільки, до якої дати воно придатне. Сайт порівнює цей список із каталогом рецептів і показує:

- які страви можна приготувати **просто зараз**;
- для решти страв — **чого саме не вистачає**.

### Що є на сайті

- **Каталог рецептів** з пошуком за назвою та фільтрами (категорія, час приготування, продукт).
- **Сторінка рецепта**: опис, час приготування, список інгредієнтів із кількістю, кроки приготування.
- **Довідник продуктів** (молоко, яйця, борошно тощо) з одиницею виміру.
- **Категорії страв** (сніданки, супи, десерти тощо). На сторінці категорії видно всі її рецепти.
- **Додавання, редагування й видалення** рецептів, продуктів і категорій.
- **Реєстрація та вхід**.
- **Профіль користувача**: перегляд і редагування даних про себе, історія приготованих страв.
- **Мій холодильник**: продукти користувача, їх кількість і термін придатності.
- Кнопка **«Приготувала»** на сторінці рецепта: додає страву до історії. Продукти з холодильника при цьому автоматично не списуються (спрощена версія).
- Сторінка **«Про сайт»** з контактною інформацією.

## REST API

### Загальні правила

- Усі запити починаються з `/api/v1`. Адреси пишемо без слеша в кінці, наприклад `/api/v1/recipes`.
- Дані передаються в форматі **JSON**.
- Назви ресурсів у множині, дію задає HTTP-метод (`GET`, `POST`, `PUT`, `DELETE`). Для зміни використовуємо тільки `PUT`, об'єкт передається повністю.
- Успішне видалення повертає `204` без тіла.
- Поки що авторизації немає, усі реалізовані ендпоінти відкриті. Авторизацію додамо в наступних завданнях. API не зберігає стан між запитами, тому дані авторизації передаватимуться в кожному запиті (заголовок `Authorization`).
- **TBD:** пагінація списків (`?page=1&limit=20`). Зараз списки повертаються повністю.

### Формат помилок

Усі помилки мають однаковий вигляд. Поле `detail` містить пояснення, а для помилок у даних є ще `errors` зі списком проблемних полів.

```json
{
  "detail": "Некоректні дані.",
  "errors": {
    "name": ["Категорія з такою назвою вже існує."]
  }
}
```

```json
{
  "detail": "Категорію не знайдено."
}
```

### Статуси помилок

| Статус | Коли повертається |
|---|---|
| `400` | Некоректні дані в тілі запиту або параметрах: не заповнене поле, назва вже зайнята, неіснуючий `category_id`, `max_time=abc` тощо |
| `404` | Об'єкта з таким id немає |
| `409` | Дані правильні, але дія суперечить поточному стану: не можна видалити категорію, у якій є рецепти, і продукт, який використовується в рецептах |
  

### Продукти (довідник)

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `GET /products` | Список продуктів | `?search=молоко` (необов'язково) | `200` + список | — |
| `GET /products/{id}` | Один продукт | — | `200` + продукт | `404` |
| `POST /products` | Додати продукт | `{"name", "unit"}` | `201` + створений продукт | `400` |
| `PUT /products/{id}` | Змінити продукт | `{"name", "unit"}` | `200` + оновлений продукт | `400`, `404` |
| `DELETE /products/{id}` | Видалити продукт | — | `204` | `404`, `409` (продукт є в рецептах) |

`unit` — одиниця виміру: `g` (грами), `ml` (мілілітри), `pcs` (штуки).

### Категорії страв

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `GET /categories` | Список категорій | — | `200` + список | — |
| `GET /categories/{id}` | Категорія з її рецептами | — | `200` + категорія зі списком рецептів | `404` |
| `POST /categories` | Додати категорію | `{"name"}` | `201` + створена категорія | `400` |
| `PUT /categories/{id}` | Змінити категорію | `{"name"}` | `200` + оновлена категорія | `400`, `404` |
| `DELETE /categories/{id}` | Видалити категорію | — | `204` | `404`, `409` (у категорії є рецепти) |

### Рецепти

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `GET /recipes` | Список рецептів | `?search=омлет&category_id=1&max_time=30&product_id=2` (усі необов'язкові) | `200` + список | `400` (параметр не число) |
| `GET /recipes/{id}` | Сторінка рецепта | — | `200` + рецепт | `404` |
| `POST /recipes` | Додати рецепт | див. приклад нижче | `201` + створений рецепт | `400` |
| `PUT /recipes/{id}` | Змінити рецепт (передається повністю) | як у `POST` | `200` + оновлений рецепт | `400`, `404` |
| `DELETE /recipes/{id}` | Видалити рецепт разом із кроками та інгредієнтами | — | `204` | `404` |

Параметри `GET /recipes` можна поєднувати: `search` це частина назви, `category_id` лише рецепти цієї категорії, `max_time` час приготування не довше за вказаний (у хвилинах), `product_id` рецепти, де є цей продукт.


Тіло запиту `POST /recipes` (і `PUT /recipes/{id}`):

```json
{
  "name": "Омлет",
  "description": "Швидкий сніданок",
  "cooking_time_min": 15,
  "category_id": 1,
  "steps": [
    "Збити яйця з молоком",
    "Смажити на середньому вогні"
  ],
  "ingredients": [
    {"product_id": 1, "quantity": 3},
    {"product_id": 2, "quantity": 100}
  ]
}
```


Відповідь `GET /recipes/3` (так само повертаються `POST` і `PUT`):

```json
{
  "id": 3,
  "name": "Омлет",
  "description": "Швидкий сніданок",
  "cooking_time_min": 15,
  "category": {"id": 1, "name": "Сніданки"},
  "steps": [
    "Збити яйця з молоком",
    "Смажити на середньому вогні"
  ],
  "ingredients": [
    {"product": {"id": 1, "name": "Яйця", "unit": "pcs"}, "quantity": 3.0},
    {"product": {"id": 2, "name": "Молоко", "unit": "ml"}, "quantity": 100.0}
  ]
}
```

## Заплановані ендпоінти

Ці ендпоінти ще не реалізовані. Без авторизації будуть доступні `POST /auth/register`, `POST /auth/login`, усі `GET` для продуктів, категорій і рецептів (без `can_cook`) та `GET /about`. Усі інші ендпоінти потребуватимуть авторизації.

### Авторизація та профіль

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `POST /auth/register` | Реєстрація | `{"username", "email", "password"}` | `201` + дані користувача | `400`|
| `POST /auth/login` | Вхід | `{"email", "password"}` | `200` + дані для авторизації (**TBD**) | `401` |
| `GET /users/me`  | Мій профіль | — | `200` + дані користувача | `401` |
| `PUT /users/me`  | Змінити дані про себе | `{"username", "email"}` | `200` + оновлені дані | `400`, `401`|

### Рецепти, які можна приготувати

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `GET /recipes?can_cook=true` | Лише рецепти, які можна приготувати з мого холодильника | ті самі параметри + `can_cook=true` | `200` + список | `401` |

До відповіді `GET /recipes/{id}` для авторизованого користувача додасться поле `missing_ingredients` — чого не вистачає саме йому:

```json
"missing_ingredients": [
  {"product_id": 2, "name": "Молоко", "needed": 100, "in_fridge": 0, "unit": "ml"}
]
```

### Мій холодильник

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|
| `GET /fridge/items` | Що зараз є в холодильнику | — | `200` + список | `401` |
| `POST /fridge/items`  | Додати продукт у холодильник | `{"product_id", "quantity", "expires_at"}` | `201` + створений запис | `400`, `401`, `404` (немає такого продукту) |
| `PUT /fridge/items/{id}`  | Змінити кількість або термін придатності | `{"quantity", "expires_at"}` | `200` + оновлений запис | `400`, `401`, `404` |
| `DELETE /fridge/items/{id}`  | Прибрати продукт із холодильника | — | `204` | `401`, `404` |

Тіло запиту `POST /fridge/items`:

```json
{
  "product_id": 1,
  "quantity": 6,
  "expires_at": "2026-10-20"
}
```

Відповідь `201`:

```json
{
  "id": 7,
  "product": {"id": 1, "name": "Яйця", "unit": "pcs"},
  "quantity": 6,
  "expires_at": "2026-10-20"
}
```

### Історія приготованого

| Метод і URL | Призначення | Body / параметри | Успішна відповідь | Помилки |
|---|---|---|---|---|

| `GET /cooked`  | Моя історія приготованого | `?page=1&limit=20` | `200` + список | `401` |

## Як запустити проєкт

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Сервер буде на `http://127.0.0.1:8000`, а API на `http://127.0.0.1:8000/api/v1`

Фронтенд працює на `http://localhost:3000`. Бекенд дозволяє запити з цієї адреси через CORS, налаштування `CORS_ALLOWED_ORIGINS` у `config/settings.py`.

У папці `postman/` лежить колекція запитів з прикладами відповідей. Її можна імпортувати в Postman, змінна `base_url` дорівнює `http://127.0.0.1:8000/api/v1`.
